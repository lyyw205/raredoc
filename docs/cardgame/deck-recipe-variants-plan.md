# 덱 레시피 — "한 덱의 다양한 구성" 표현 계획 (코어+플렉스 / 플레이카드 통합)

> 상태: **설계 확정(아이디에이션 완료) · 미구현**
> 대상 화면: `/cardgame/decks/[id]` (덱 상세) — `표준 레시피` 섹션 재설계
> 관련: [cardgame-ui-plan.md](./cardgame-ui-plan.md) · [meta-pipeline-multisource.md](./meta-pipeline-multisource.md) · [cardgame-backlog.md](./cardgame-backlog.md)

## 1. 배경 / 문제

덱 상세의 `표준 레시피`는 현재 **인쇄판 단위**로 카드를 나열하고, 각 줄에 "전체적으로 얼마나 쓰이는지"(채용률·평균 장수)만 보여준다. 두 가지가 표현되지 않는다:

1. **같은 성능·다른 인쇄판** — 같은 플레이 카드(예: `드래펄트 ex`)가 일반/SAR/알트아트 등 여러 인쇄판으로 **레시피에 여러 줄로 흩어진다**. 성능은 동일하고 **시세만 다르다**(자금 부족 → 저가판, 여유 → 고가판). 지금은 한 카드가 여러 줄로 쪼개져 채용률이 분산돼 보인다.
2. **유저마다 갈리는 구성** — 핵심은 같아도 나머지(서브어태커·드로우·테크)가 리스트마다 다르다. 현재는 "평균 한 벌"로 뭉개져 *어디서 선택이 갈리는지*가 안 보인다.

## 2. 데이터 사실 (조사 완료, 2026-06-18)

- **`DeckRecipeCard`** 컬럼: `archetypeId · cardName · setCode · number · category(pokemon/trainer/energy) · avgCount · adoptionRate · logicalCardId(=Prisma cardId) · isCore · region`. region=`INTL` 고정 사용.
- **인쇄판 분산 실재**: `dragapult-ex`에서 `Dragapult ex`가 TWM 130(79%) · TWM 200/SAR(8%) · PRE 073(5%) · ASC 160(3%) 등 **여러 행**으로 존재.
- **`gameCardId`(게임상 같은 카드)** 가 이미 모델에 있음(`LogicalCard.gameCardId`). 인쇄판들을 "같은 플레이 카드"로 묶는 단일 키. `getCardAdoption()`은 이미 이걸로 통합 집계함 — `getArchetypeRecipe()`만 아직 미적용.
- **개별 제출 리스트 풍부**: `TournamentStanding.decklist`(JSON) 보유 — `dragapult-ex` 618개. 구조: `{ pokemon|trainer|energy: [{ set, name, number, count }] }`. 한 리스트 내에선 한 카드를 **단일 인쇄판으로 등록**하는 게 절대다수(2+2 인쇄판 혼합은 드묾) → 진짜 변동은 (A)어떤 인쇄판 (B)몇 장 (C)어떤 플렉스.
- ⚠ **gameCardId 재판 병합 정합성 의존**: `Dragapult ex`가 `gc_1c65…`(TWM 130/200)와 `gc_545b…`(PRE/ASC) **두 게임카드로 갈려** 있음. 교차세트 재판이 같은 플레이 카드인데 미병합인지 별개 카드인지 **확인 필요** — 통합 품질이 여기에 좌우됨(§7).

## 3. 확정 설계 (5개 결정 — 인터뷰 결과)

| # | 결정 | 내용 |
|---|---|---|
| 1 | **슬롯 = 플레이 카드** | 성능 같은 인쇄판은 `gameCardId`로 **1줄 통합**. 채용률·장수 통합. 덱 페이지엔 버전 picker 없이 **인라인 💰 시세 힌트(가격대)만**. 버전 선택·구매는 카드 상세(`/cards/[id]`)로 위임 |
| 2 | **코어 + 플렉스** | **코어**=거의 모든 덱이 채용·고정(합의 장수 `×N`) / **플렉스**=갈리는 결정 지점(채용률 %) |
| 3 | **플렉스 = 카테고리 그룹** | 포켓몬/트레이너/에너지(+도구·스타디움)로 그룹. 의미 단위 "역할(서브어태커/드로우…)" 라벨은 **추후**(데이터 없음) |
| 4 | **버전 = 시세 힌트만** | 슬롯에 `💰 ₩저가~고가`만. 덱 페이지는 *구성 이해*에 집중, 쇼핑/견적 설정은 분리 |
| 5 | **하단 실제 리스트 N개** | 합성 뷰(학습) + 최근 입상 실제 60장(복사). 선수·견적·리스트뷰어 링크. 군집 이름표는 추후 |

## 6. 구현 단계

### P0 — 서비스: gameCardId 통합 (`getArchetypeRecipe`)
- `DeckRecipeCard`(INTL) 행을 `logicalCardId → gameCardId`로 묶어 **플레이 카드 1개 = 1슬롯**으로 통합.
- 통합 슬롯 필드: 대표 인쇄판(가성비=최저 시세 1장) · 인쇄판 목록 · `priceMin/priceMax`(시세 힌트) · 통합 `adoptionRate` · 합의 `count`.
- 통합 채용률: ~~(P0) 인쇄판 합산 근사~~ → **✅ 정확 재집계 완료** — 최근 14일(INTL·source≠null) `TournamentStanding.decklist` 원본에서 직접 집계. 분모=윈도우 내 deckKey **덱리스트 보유** standings(미수집 standing 제외 → "거의 모든 덱"이 ~100% 로 정직). 한 리스트의 같은 카드 여러 인쇄판은 1회만 카운트. 윈도우 비면 DeckRecipeCard 합산 근사로 폴백.
- `gameCardId` 없는 카드(기본 에너지 등 `logicalCardId=null`)는 `cardName+set`을 자기 키로 무회귀.

### P1 — 코어/플렉스 분류
- **코어**: 통합 채용률 ≥ **80%** → 고정 표시(`×N` 합의 장수).
- **플렉스**: **12%~80%** → 슬롯 옵션(% 표시).
- **마이너**: < **12%** → 기본 접기("마이너 테크 N장 ▾"). 노이즈 컷.
- (임계값은 상수로 빼서 튜닝 가능하게.)

### P2 — UI: 표준 레시피 → 코어+플렉스
- `RecipeSection` 재작성: `■ 코어`(카테고리 소그룹) + `■ 플렉스 슬롯`(카테고리 소그룹, 옵션 나열).
- `RecipeRow`: `×N`(코어) / `%`(플렉스) + **인라인 💰 가격대**. 썸네일=가성비 인쇄판. 클릭→`/cards/[id]`.

### P3 — 실제 리스트 (재사용)
- 기존 `ResultsTimeline` 유지. 선택: 줄당 견적(`deckCostBudget`) 노출 + 정렬(최근 입상 + 견적 다양성 N=3 강조).

### P4 — 후속 (별도 차수)
- **역할 라벨**(서브어태커/드로우/…): 자동추론+검수 레이어 → 플렉스 그룹 라벨 고도화(결정 #3 추후분).
- **군집 이름표**(표준형/저예산형…): 618리스트 클러스터링 → 실제 리스트 N개에 라벨(결정 #5 추후분).
- ~~**정확 채용률**: 원본 리스트 재집계~~ → ✅ 완료(P0 §6 참조).
- (선택) 예산 빌드 생성기: 슬롯별 가성비+최빈 플렉스로 완성 60장 1벌 + 총 견적.

## 7. 리스크 / 주의

- **gameCardId 재판 병합**(§2 ⚠): 교차세트 재판 미병합 시 통합이 덜 됨(같은 카드가 여전히 2슬롯). P0 착수 전 `Dragapult ex` gc 2종이 동일 플레이 카드인지 1건 점검 → 필요 시 재판 병합 보정 별도 태스크.
- **동결 카드팩 무관**: 이 작업은 EN/KR 매핑·정체성 변경 없음(읽기 집계만). `PROTECTED_GROUPS` 건드리지 않음.
- **region 격리**: 모든 집계 `region='INTL'` 고정 유지(멀티소스 P0 규약).
- **시세 데이터 공백**: `priceMin/Max` 미수집 카드는 `💰 —`(힌트 생략), 견적 위젯 기존 폴백과 일관.

## 8. 미해결 질문 (후속 인터뷰 가능)

- 코어/플렉스 임계값 최종치(80/12 제안값 검증).
- 플렉스 옵션 정렬(채용률순 vs 시세순) · 슬롯당 최대 노출 수.
- 실제 리스트 N=3 선정 기준(최근순 vs 견적 분산 vs 입상순).
