## 4. 시세 수집 (Price)

상세 설계·출처 근거: [`agents/price-collector-plan.md`](./agents/price-collector-plan.md)

### 사전 준비 (최초 1회)
```bash
npm run prisma:push          # Price.marketPrice 칼럼 등 반영
npm run prisma:generate
npm run seed:source          # 시세 출처 9개 시드
```

### ⭐ 한 방에 전부 (오케스트레이터, 권장)
```bash
npm run sync:prices:all
```
출처를 순서대로 실행 → 일시 실패 자동 재시도(지수 백오프) → 마지막에 요약표 출력.

| 옵션 | 설명 | 예시 |
|---|---|---|
| `--only=<key>` | 특정 출처만 (`en`, `jp-yuyu`) | `npm run sync:prices:all -- --only=en` |
| `--en-limit=N` | EN 앞 N개 세트만(테스트) | `npm run sync:prices:all -- --en-limit=5` |
| `--retries=N` | 출처별 재시도 횟수(기본 2) | `npm run sync:prices:all -- --retries=3` |

### 출처별 단독 실행
| 명령 | 출처 | 옵션 |
|---|---|---|
| `npm run sync:prices:en` | EN — pokemontcg.io (TCGplayer USD + Cardmarket EUR) | `-- --set=sv3pt5`, `-- --limit=3` |
| `npm run sync:prices:jp:yuyu` | JP — yuyu-tei (販売 호가 + 買取 매입가) | `-- --set=sv02a`, `-- --sell-only`, `-- --buy-only` |

> ⚠️ JP yuyu는 `scripts/sync-prices-yuyu.ts`의 `SET_MAP`에 등록된 세트만 수집(현재 `sv02a`=151, `m05`=아비스아이). 세트 추가는 `SET_MAP`에 `yuyu코드: "우리setId"` 한 줄.

### 로그 읽는 법
```
17:47:56 ▶ 시세 수집 오케스트레이터 시작 — 출처 2개, 재시도 2회
17:47:56 ━━ EN pokemontcg.io (시도 1/2) ━━
17:49:42   ✓ EN pokemontcg.io: written=203 dup=128 unmatched=0 (15.1s)
17:48:20 ═══ 요약 ═══
  출처                   결과  written    dup  unmatch  warn  err
  EN pokemontcg.io      OK       203    128        0     0    0
  JP yuyu-tei           OK       169    851        0     0    0
17:48:20 ◀ 완료: 총 written=372, 전부 성공 ✓, 39.1s
```
- **written**: 새로 적재 / **dup**: 오늘 이미 받아 갱신만(멱등, 정상) / **unmatch**: 우리 DB에 없는 카드(추측 안 함) / **warn·err**: 경고·치명에러
- 종료코드: 전부 성공 `0`, 일부 실패 `1`

### 미구현 (예정)
PokeTrace Pro 등급 · hareruya2(JP 등급) · eBay(EN+KR 한국어) · KR USD→KRW 환산 · MarketStat 야간 집계.

## 5. 카드 데이터 수집 (시대별)

카드 카탈로그(세트·카드·이미지·메타)를 시대(era)별로 수집·보강하는 파이프라인.
보통 **신팩 발매**나 **시대 미보유분 채울 때**만 실행. 시세와 별개.

### 시대 코드
`sm`(썬문) `xy` `bw`(블랙화이트) `dppt`(다이아펄/플라티나) `hgss` `l`(레전드) `pcg`(PCG) `pmcg`(구판) `neo` `adv` `ecard` 등.

### 시대 수집 표준 흐름 (예: SM)
package.json에 명령으로 등록된 건 **SM 세트뿐**이다. 다른 시대는 `tsx scripts/<파일>` 로 직접 실행.
```bash
npm run sync:sm:en            # EN 카탈로그 (pokemontcg.io)
npm run enrich:sm:meta        # 메타 보강 (tcgdex)
npm run sync:sm:bulbapedia    # JP 데이터 (Bulbapedia)
npm run scrape:sm:illustrator # 일러스트레이터 스크랩
npm run seed:sm:koreanames    # 한글명 시드
npm run verify:sm             # 검증 리포트
```

### 다른 시대 (npm 등록 안 됨 → tsx 직접 실행)
| 작업 | 파일 패턴 | 예시 |
|---|---|---|
| EN 카탈로그 | `sync-<era>-pokemontcgio.ts` | `npx tsx scripts/sync-bw-pokemontcgio.ts` |
| JP(Bulbapedia) | `sync-<era>-bulbapedia-jp.ts` | `npx tsx scripts/sync-dppt-bulbapedia-jp.ts` |
| 메타 보강 | `enrich-<era>-meta-tcgdex.ts` | `npx tsx scripts/enrich-xy-meta-tcgdex.ts` |
| 일러스트 스크랩 | `scrape-<era>-illustrator-bulbapedia.ts` | `npx tsx scripts/scrape-pcg-illustrator-bulbapedia.ts` |
| 이미지 스크랩 | `scrape-<era>-images-bulbapedia.ts` | `npx tsx scripts/scrape-neo-images-bulbapedia.ts` |
| 이미지 업로드 | `upload-<era>-images-supabase.ts` | `npx tsx scripts/upload-pcg-images-supabase.ts` |
| 한글명 시드 | `seed-<era>-koreanames.ts` | `npx tsx scripts/seed-bw-koreanames.ts` |
| 검증 | `phase-a-verify-<era>.ts` | `npx tsx scripts/phase-a-verify-neo.ts` |

> 실제 보유 시대 파일 목록은 `ls scripts/` 로 확인. era 슬러그만 바꿔 끼우면 된다.

## 7. 자주 겪는 상황

### 외부 API가 504 / 타임아웃
정상. 외부 사이트가 가끔 죽는다. **그냥 다시 실행**하면 멱등이라 이미 받은 건 `dup`으로 건너뛰고 빠진 것만 채운다. `sync:prices:all`은 자동 재시도까지 한다.

### `written=0`, `dup`만 가득
이미 오늘 수집했다는 뜻(하루 1행/출처). 정상.

### `⚠ 파싱 0건` / `⚠ 전부 unmatched` 경고
- 파싱 0건 → 사이트 HTML 구조 변경 의심, 해당 스크래퍼 정규식 점검
- 전부 unmatched → 세트 매핑/번호 형식 불일치, `SET_MAP`·번호 매칭 점검

### `PriceSource 미시드` 에러
`npm run seed:source` 먼저 실행.

### 전 EN 세트가 너무 오래 걸림 (세트 150+개, 수십 분)
백그라운드 + 로그파일:
```bash
npm run sync:prices:en > sync-en.log 2>&1 &
```

### 스키마 바꿨는데 타입 에러
`npm run prisma:push && npm run prisma:generate` 후 다시.

## 부록 — 시세 파이프라인 구조 (개발자용)

```
scripts/
├── lib/price-sync-lib.ts        공통: 로거, 지수백오프 재시도 fetch, 멱등 upsert, sanity 검증
├── sync-prices-pokemontcg.ts    EN  — run(opts) + 단독 실행
├── sync-prices-yuyu.ts          JP  — run(opts) + 단독 실행 (SET_MAP)
└── sync-prices-all.ts           오케스트레이터 (ALL_JOBS 등록)
```

**새 시세 출처 추가법**
1. `scripts/sync-prices-<출처>.ts`에 `export async function run(opts): Promise<SyncResult>` 작성
2. `sync-prices-all.ts`의 `ALL_JOBS`에 `{ key, label, run }` 한 줄 추가
3. `scripts/seed-price-source.ts`에 PriceSource 행 추가 후 `npm run seed:source`

> 원칙: 가격 수집은 **결정적 코드**로만(LLM 미사용 — 비용·환각 위험). 비정형 파싱/모니터링이 꼭 필요할 때만 별도 에이전트(Layer 2) 검토.
