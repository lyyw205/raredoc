# pack-list-check — 카드팩 리스트 ↔ DB 6필드 대조 파이프라인

사용자가 붙여넣은 팩 카드 리스트를 DB(**JP 기준**)와 **6필드**로 대조하고, 안전한 in-DB 수정만 규칙대로 적용한 뒤 `docs/list_match_log.md`에 기록한다.

> **이 스킬의 존재 이유**: 매번 같은 방법으로 점검하기 위해서다. 과거에 중간부터 임의로 다른 방식으로 체크하거나 사용자 확인 없이 수정해 신뢰를 깬 적이 있다. **파이프라인·금지사항·유의사항은 고정**이고, 바뀌는 것은 `references/comparison-sources.md`의 **비교 자료뿐**이다. 절차를 "개선"하거나 "더 효율적으로" 바꾸지 말 것 — 바꿀 필요가 보이면 먼저 사용자에게 말한다.

대조 6필드: **① 카드명 ② 카드번호·세트총장수 ③ 진화단계 ④ 타입 ⑤ 레어도** (+ ex 표기 대소문자). 시세는 dex 미적재라 제외.

---

## 🚫 절대 금지 (HARD STOP — 어기면 작업 중단·되돌림)

1. **EN 세트를 리스트와 번호로 대조하지 않는다.** 검증은 **JP 세트 1개**만 대상. EN은 번호 체계가 달라(예: 리트윅 라인 위치 차이) 같은 번호끼리 맞대면 **대량 허위 불일치**가 쏟아진다(White Flare 사건). EN 세트를 끌어와 리스트와 비교 = 금지. (단, *수정 범위 판정*을 위해 같은 LogicalCard의 EN RegionCard 값을 **읽어보는 것**은 허용 — 아래 수정규칙 참조. "EN을 리스트와 대조"와 "오류가 어느 계층에 있는지 DB를 읽기"는 다른 행위다.)
2. **타깃 세트를 장수(카드 수)로 고르지 않는다.** 반드시 **JP 카드명 덤프로 타깃을 확인**한다. 장수 폴백은 엉뚱한 세트를 집어온다(예: SVOM을 옛 jp-scd로 오인). 코드로 찾고 JP명으로 검증.
3. **리스트에 있는 필드를 외부 사이트(Bulbapedia 등)로 다시 확인하지 않는다.** 사용자가 준 리스트가 그 필드의 **1차 권위**다. 리스트에 없거나 모호한 필드(레어도가 잘린 경우 등)에 한해서만 외부 출처를 본다.
4. **수정 범위를 사용자에게 "고르라고" 묻지 않는다.** 오류가 어느 계층(Card / JP·EN·KR RegionCard)에 있는지는 **데이터를 읽어 내가 판정**한다. 판정 결과 하나의 올바른 수정안을 제시하고 **적용 여부(예/아니오)만** 확인받는다. 스코프 선택지 메뉴를 만들지 않는다.
5. **동결팩의 EN/KR 연결(RegionCard 링크·트레이너 이름 대응)을 바꾸지 않는다.** 동결 목록·가드는 `scripts/lib/protected-groups.ts`. 메타데이터(subtypes/types/supertype/rarity)만 손대고, 연결은 불변. raw prisma·SQL 로 가드를 우회하지 않는다.
6. **즉흥적으로 절차를 바꾸지 않는다.** 새 비교 방식·새 출처가 필요해 보이면 `references/comparison-sources.md`에 추가하자고 **사용자에게 먼저 제안**한다. 그 자리에서 새 방식으로 체크하고 수정하지 않는다.
7. **이 점검 중에 대량 신규 수집·구조 변경을 하지 않는다.** 미수집·구조 문제는 **발견·로그만** 하고, 수집/재편은 별도 전담 패스로 미룬다.

## 수정 규칙 (무엇을 언제 고치나)

| 종류 | 처리 |
|---|---|
| **EX→ex 대소문자** (modern ex가 옛 대문자 `EX`로 라벨) | **자동 적용**(매번 안 물음, **동결팩 포함**). 사용자 사전승인됨. |
| 그 **외 모든 수정**(레어도·진화단계·타입·이름 등) | **건건 확인**. 증거 제시 후 예/아니오 받고 적용. |

**수정은 "틀린 곳을 전부 일관 교정"이 원칙이다(부분만 고치지 않는다).**
- 오류가 어느 계층에 있는지 먼저 읽는다: `Card.rarity`(LC 공유값) / `RegionCard.rarity`(인쇄본별, JP·EN·KR 각각).
- **JP만 틀렸으면 JP RegionCard만** 고친다(예: SV11B UR→SR, SV6a 스왑).
- **JP·EN·KR + Card가 다 같은 값으로 틀렸으면 전 계층을 고친다**(예: SV5a ACE SPEC 오배정 — 3국 동일오류). 이건 "EN을 본다"가 아니라 "같은 오류가 모든 인쇄본에 박혀 있어 일관되게 고치는 것".
- 표시 경로를 기억: dex는 `RegionCard.rarity ?? Card.rarity`로 읽고, `/cards` 단독 페이지는 `Card.rarity`를 직독한다. 그래서 어느 계층을 비워두면 어디서 틀리게 보이는지 따져 범위를 정한다.

**DB를 바꾸는 스크립트는 반드시 `assertWritable()`로 가드한다.** 동결팩이면 dry-run으로 영향 확인 → 사용자 확인 → `--apply --allow-protected`. 가드 단일출처: `scripts/lib/protected-groups.ts` (`hasAllowProtectedFlag(argv)` 동반).

## 파이프라인 (모든 팩에 동일 적용 — 순서 불변)

### 0. 리스트를 임시파일로 저장
사용자가 붙여넣은 리스트를 `/tmp/<코드>.txt`에 그대로 저장한다. 포맷·파싱은 `references/comparison-sources.md`("리스트 포맷") 참조.

### 1. 타깃 JP 세트 확정 (JP명으로 검증)
- 코드(SV5a 등)·팩명으로 후보 세트를 찾는다. `cardPackId`(setGroup)로 묶인 JP/KR/EN 세트 중 **region=JP**가 타깃.
- **JP 카드명 앞 8장 + 뒤 6장을 덤프해 리스트와 같은 팩인지 눈으로 확인**한다(🚫#2). 엉뚱하면 코드로 다시 찾는다.

### 2. 비교 스크립트 실행
`scripts/compare-list.ts`를 **그대로** 쓴다(매번 새로 짜지 말 것). 인자로 리스트 파일과 타깃을 준다:
```bash
npx tsx .claude/skills/pack-list-check/scripts/compare-list.ts --list /tmp/<코드>.txt --pack <cardPackId>
# 또는 --set <jpSetId>
```
이 스크립트가 6필드 diff + 포켓몬 종명 양방향 검증(CSV)을 한 번에 돌린다. 검증 방법·DB 읽기 경로·매핑은 전부 `references/comparison-sources.md`에 있고, 스크립트는 그걸 구현한 엔진이다.

### 3. 이슈 분류
스크립트가 뱉은 이슈를 분류한다:
- **EX→ex** → 자동수정 대상(아래 4).
- **레어도/단계/타입/이름 오류** → 어느 계층이 틀렸는지 DB를 더 읽어 범위 판정 → 사용자 확인 대상.
- **리스트 측 오타**(DB가 실제와 맞고 리스트가 틀림) → DB 미변경, 로그에만 "리스트 오타"로 남김.
- **EN링크 갭·미수집·기본에너지 초과** → 발견·로그만(🚫#7).

### 4. 안전 수정 적용
- EX→ex: `scripts/`에 일회용 `fix-<코드>-ex.ts`를 만들어 `assertWritable`+(동결이면)`--allow-protected`로 적용.
- 그 외 확인받은 수정: 마찬가지로 일회용 fix 스크립트, dry-run→확인→apply.
- **즉석 prisma/SQL 금지**(🚫#5).

### 5. 재검증
수정 후 `compare-list.ts`를 다시 돌려 **이슈 0**(또는 의도된 잔여만)인지 확인한다.

### 6. 임시 스크립트 정리
`check-*.ts`·`fix-*.ts` 등 일회용 스크립트는 삭제한다(레포에 남기지 않음). 비교 엔진(`compare-list.ts`)은 스킬 자산이라 유지.

### 7. 로그 기록 → `docs/list_match_log.md`
아래 형식대로 누적 기록한다(파일이 외부에서 수정될 수 있으니 편집 전 재-read).
- **요약표 1행**: `| 날짜 | 팩(코드/JP명) | DB setId | region | 장수 | 결과 |`
- **적용한 DB 변경** 목록에 한 줄(무엇을 어느 계층에서 왜).
- **팩별 상세** 섹션: 일치 필드·교정 내역·미해결.
- 반복되는 패턴이면 **Cross-cutting 패턴 표**(M1~)에 묶는다.

### 8. 보고
사용자에게 한국어로: 일치한 필드, 교정 내역(계층 명시), 미해결/보류, 재검증 결과. 코드·세트명 원문은 유지.

## 유의사항 (반복해서 빠진 함정들)

- **전각/반각 정규화 필수.** 종명 대조 시 `ポリゴン２`·`Ｚ`(전각) vs DB `2`·`Z`(반각)는 정규화 안 하면 **허위 불일치**. (compare-list.ts에 내장됨 — 끄지 말 것.)
- **레어도 읽기 = `RegionCard.rarity ?? Card.rarity`** (인쇄본 우선·LC 폴백). 공유 LogicalCard는 `Card.rarity` 하나로 지역별 다른 레어도를 표현 못 한다 → 인쇄본별은 `RegionCard.rarity`가 담당.
- **진화단계 = `Card.subtypes`**(Basic/Stage 1/Stage 2), **타입 = `Card.types`**, **분류 = `gameCard.supertype ?? Card.supertype`**. (compare-list.ts가 이 경로로 읽음.)
- **KR 번호 재배열은 정체성 정상이다.** 한국판은 트레이너를 가나다순으로 재배열해 KR번호 ≠ JP번호일 수 있다. **LC 연결이 맞으면 정상** — 번호를 "고치지" 말 것.
- **하이클래스팩 본탄은 무레어도(전부 `-`/None)일 수 있다.** 가짜 레어도를 채우지 말고, 무레어도면 무레어도로 둔다(M2a 교훈). 판별: 리스트 본탄 일반 카드가 전부 레어도 없음.
- **덱/박스 제품의 동봉 기본에너지가 DB에 초과로 들어있을 수 있다.** "기본에너지 차이"로 분류하고 우선순위 낮음 — 사용자 결정 전까지 삭제하지 않는다.
- **리스트도 오타가 날 수 있다.** DB가 실제와 맞고 리스트만 틀리면(예: 일부 진화단계 오표시) DB는 그대로 두고 로그에 "리스트 오타"로 남긴다.
- **시크릿/패럴렐은 본탄과 별행**이다 — 레어도(AR/SR/SAR/UR…)까지 맞는지 확인.

## 유동부 — 비교 자료는 여기만 고친다

검증에 쓰는 **자료·출처·매핑·파싱 규격**은 전부 `references/comparison-sources.md`에 모았다. 새 검증 자료(새 CSV, 새 레어도 출처, 새로 대조할 필드 등)가 생기면 **그 파일과 `scripts/compare-list.ts`만** 고치고, 위 파이프라인·금지·유의는 건드리지 않는다.

관련 메모리: 종명/레어도 출처·동결 규칙은 프로젝트 메모리에도 있다(EX→ex 자동승인·한국어 응답·레어도 출처 우선순위·동결 카드팩).
