# card-check 보고 — 스칼렛 ex 도감 클레스퍼트라 KR 이미지 깨짐

## 결론 (한 줄)
클레스퍼트라(kr-sv1s #037) KR 이미지가 안 뜨는 건 정체성/연결 문제도 R2 객체 부재(404)도 아니다. R2 미러 객체는 200으로 멀쩡히 존재하지만, **그 세트에서 유일하게 리사이즈·정규화 단계를 건너뛴 원본 풀해상도(868×1212, interlaced, 1.9MB) PNG가 그대로 올라가 있어서** 프런트 이미지 최적화가 이 한 장만 처리에 실패하는 케이스다.

## 진단 분기 (kr-trainer-alignment.md 1단계 표)
- (1) lcid 오연결? 아님 — JP/EN/KR 동일 정체성(클레스퍼트라=Espathra=クエスパトラ, dex 956).
- (2) build-group 번호-zip? 아님 — 이미지 자체가 안 뜸.
- (3) R2 이미지 깨짐 → 여기 해당. 단 통상(404 부재)과 달리 **객체는 200인데 포맷/크기가 비정규**한 변종.

## 증거
- `curl -I` R2 small/large #037 = 200, Content-Length **1,910,516** (이웃 036=409,613 / 038=387,609).
- 세트 전수 content-length 스캔: **#037만 단독 이상치(3.4배)**.
- PIL/file: R2 #037 = 868×1212 interlaced RGBA, 이웃 = 400×558 non-interlaced.
- md5(R2 #037) == md5(pokemonkorea 원본 SV1S_037.png) → **원본 바이트 그대로(리사이즈 누락)**.
- backfill-kr-images-r2.ts dry-run: BROKEN(404/NULL) 0 → 200이라 현행 도구 탐지 사각지대.
- 육안: 객체 내용은 정상 카드(HP110, 037/078, Hitoshi Ariga).

## 근본 원인
KR 미러 파이프라인이 다른 카드는 400×558 비인터레이스로 정규화해 올렸는데, #037만 원본(1.9MB interlaced)이 그대로 업로드됨(같은 md5). 인터레이스+풀해상도라 프런트 렌더가 이 한 장만 실패.

## 권장 조치 (READ-ONLY라 미적용)
DB는 무변경(URL·lcid 정확). R2 객체만 이웃과 동일 규격(400×558 비인터레이스)으로 리사이즈 후 small·large 두 키 덮어쓰기 → 빌드/배포 없이 즉시 반영. ⚠ 현행 backfill-kr-images-r2.ts는 (a) 404만 대상, (b) 리사이즈 없이 raw 업로드라 그대로는 못 고친다 — 리사이즈 단계 + "200이지만 크기/포맷 비정규" 탐지 추가 필요. 동종(과거 404→raw 백필 복구) 잔여를 전 KR 세트에 크기 이상치 스윕으로 함께 점검 권장.
